# 开排 · 赛事演示脚本

建议时长：2 分 20 秒。录制时使用内置独幕剧样例，不依赖网络。

## 0:00–0:15 问题

画面：工作区首页，左侧制作脊线，中央“剧本来源”，右侧当前状态。

旁白：

> 学生剧组不缺一次生成，缺的是把剧本、走位、提示和排练修改留在同一条链路上。开排从这里开始。

动作：点击“打开样例剧本”。

## 0:15–0:35 剧本确认

画面：剧本校对页，左侧原文，右侧人物别名和下一步说明。

旁白：

> 原文始终是事实源。系统只做结构建议，人物别名、场次边界和判断不确定的关系都可以在进入排演前修正。

动作：点击“确认，下一步”，进入项目总览。

## 0:35–0:55 项目总览

画面：场次节奏、人物数量、预计时长、待处理数量、视觉方向。

旁白：

> 进入项目后，用户看到不是功能菜单，而是当前作品、下一场和真正需要处理的风险。

动作：点击“进入排演台”。

## 0:55–1:20 2D / 3D 排演

画面：2D 舞台，拖到“老陈”的位置；切换“3D 白模”保留同一位置；创建灯光提示并绑定“你终于回来了”。

旁白：

> 走位和提示共用场次坐标。提示可以绑定到具体台词或动作，而不是只写在场次旁边；同一个位置还可以切换为 3D 白模检查空间关系。

## 1:20–1:38 部门需求与影响

画面：需求转译页，保留原话，展示灯光、音乐、音响、舞美分组；进入排练与影响。

旁白：

> 导演原话被拆成部门能确认的条目，但原话和待确认项不会被抹掉。改剧本后，失去绑定的提示会进入影响队列，由用户逐条决定。

## 1:38–2:00 视觉制作

画面：视觉制作页，切换视觉族、选择导演、展示色卡比例、目标和提示词，最后应用作品。

旁白：

> 视觉不是最后换一层皮。作品拥有统一的角色、场景、道具和关键帧规则，图片、视频提示词与导出模板都引用这同一套风格。

## 2:00–2:20 交付

画面：导出页，依次展示排演准备表、部门需求单、走位提示、Fountain 与项目归档。

旁白：

> 最后交付的不是聊天记录，而是舞台监督、四个技术部门和后续版本都能继续使用的工作材料。

结束字幕：

```text
开排
从剧本到排演现场
```

## 录制检查

- 清除演示前的旧本地状态，使用样例作品。
- 确认视口为 1440×900，浏览器缩放 100%。
- 不出现 API Key、真实个人信息或外部 AI 失败弹窗。
- 录制前执行 `npm.cmd test` 和 `npm.cmd run build`。
