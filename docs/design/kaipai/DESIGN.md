## 产品命题

开排不是 AI 生成器，也不做传统项目管理后台。它是一张能持续回应修改的制作工作纸：

```text
剧本原文与证据
  → 场次 / 人物 / 道具拆解
  → 排演走位与技术提示
  → 部门需求与排练决定
  → 视觉资产与交付材料
```

任何 AI 结果都必须回到它引用的剧本行、动作或场次。原话、判断、决定和生成资产不得混成同一层信息。

## 三个结构方向

### A. Worklight 提示本（采用）

深色制作现场里放一张被工作灯照亮的纸。左侧是稳定制作脊线，中部是当前工作对象，右侧是证据与待处理项。cue 标记沿页面贯穿，是本产品唯一强记忆元素。

```text
┌──────────┬──────────────────────────┬──────────────┐
│ 制作脊线 │ 当前工作纸               │ 上下文检视器 │
│ 剧本     │ 剧本 / 表格 / 舞台 / 资产 │ 原话与依据   │
│ 拆解     │                          │ 依赖与影响   │
│ 排演     │ 当前任务与下一步         │ 版本与操作   │
│ 交付     │                          │              │
└──────────┴──────────────────────────┴──────────────┘
```

### B. Scene Console

以场次与部门横向通道为主，适合舞台监督执行，弱化剧本写作和文字校对。

### C. Production Dossier

以章节、档案页和大幅视觉资产为主，展示感最强，但不适合高频排演修改。

产品优先让导演、编剧和舞台监督在一个屏幕内连续工作，因此采用 A，同时保留 B 的时间轴思想用于节奏和 cue 展示。

## 视觉令牌

| Token | Value | 用途 |
|---|---|---|
| `--stage-950` | `#11100e` | 外部制作现场 |
| `--stage-900` | `#181613` | 导航与检视器 |
| `--paper` | `#f4f0e8` | 主工作纸 |
| `--paper-raised` | `#fffdf8` | 表单与可编辑表面 |
| `--ink` | `#1c1917` | 正文 |
| `--accent-seal` | `#b23b32` | 风险、失效、待确认 |
| `--cue` | `#c18a2d` | cue、当前步骤与焦点 |
| `--confirmed` | `#55715b` | 已确认 |

颜色不使用渐变光效。深色区域来自舞台后台，浅色区域来自工作灯下的剧本页。

## 字体与排版

- 工作流和控件：`PingFang SC / Microsoft YaHei / system-ui`
- 剧名、章节、剧本与数字：`Source Han Serif SC / Songti SC`
- 编号、cue、时间和状态：`Cascadia Mono / Consolas`
- 正文最大宽度约 65 个汉字；表格允许高密度，创作页面保持呼吸感。

## 信息状态

- 来源：`原文`、`AI 建议`、`用户确认`、`系统派生`
- 工作状态：`draft`、`review`、`confirmed`、`delivered`
- 资产状态：`prompt-ready`、`queued`、`candidate`、`selected`、`stale`、`failed`
- 风险只用朱红；cue 与当前导航用琥珀；确认完成用苔绿。

## 页面层级

1. 作品库：多作品搜索、当前作品、归档导入导出。
2. 项目总览：当前阶段、场次/人物/提示数量、待处理影响、下一任务。
3. 剧本与版本：原文编辑、解析警告、别名合并、版本差异。
4. 场次拆解：主表只显示场景、地点、人物、时长和状态；详情进入检视器。
5. 人物关系：人物卡、关系证据、把握不足的关系标记。
6. 排演台：2D 舞台、演员与 AB 角、走位、技术提示、顺序预览；3D 白模按同一坐标数据派生。
7. 部门需求：保留导演原话，按灯光、音乐、音响、舞美拆分，状态与责任人明确。
8. 排练影响：把笔记整理为决定、问题、待办；剧本改动产生逐项影响。
9. 视觉制作：10 个视觉族、24 位精选导演、角色/场景/道具/关键帧/海报提示词。
10. 交付：排演包、部门单、cue 表、视觉圣经和 Fountain/CSV/HTML/项目归档。

## 交互约束

- 所有操作支持键盘焦点；轮播式导航不使用。
- 弹层只用于作品库等跨上下文操作，字段编辑优先在页面内或右侧检视器完成。
- 删除作品、外部付费生成等高风险动作必须明确确认。
- 手机只承载查看、确认和排练笔记；复杂表格、舞台和资产编排以桌面和平板为主。
- 无 API 时所有核心页面仍可运行，来源标记显示“仅本地处理”。
