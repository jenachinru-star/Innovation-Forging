### 2.2 评审环境约束（关键）

原文：`The backend serves static dist/index.html and evaluates with a headless browser.`

- 评审**不启动我们的 Node 服务**，核心流程不得在运行时依赖 `/api`。
- 字体、样式、脚本必须本地可用；外部 URL 会被单独记录。
- 压缩包 tar.gz，站点上限约 500 MiB。

### 2.3 真实使用者材料

来源：编导提供的工作说明（学生剧组视角，已限定为“规模小、预算低、一人多岗、多在小剧场演出”，不代表商业组）。

**六阶段**：剧本创作 → 组建剧组 → 基础排练 → 剧目打磨 → 方案定稿 → 剧场合成与演出。

**分工**：导演、编剧、演员，技术部门为音乐、音响、舞美/服化道、灯光。

三项必须支持的事实：

| 事实 | 设计影响 |
| --- | --- |
| 「音乐」与「音响」是两个部门 | 提示与需求必须分部门建模 |
| 存在 AB 角 | 角色与演员多对多；每名演员可有独立排练记录与走位 |
| 编剧关注铺垫—高潮—结尾的节奏与时长 | 分析需含结构与时长视图 |

**三个痛点**（核心价值来源）：编剧材料整合困难、导演向技术部门转译困难、日常信息散乱不同步。

## 4. 产品定位

**一句话**：把零散的创作想法和口头沟通，变成各部门同步、可执行、可追溯的工作材料。

**主要使用者**：学生剧组与小剧团的导演、编剧、舞台监督。
**非目标**：专业院团排期与预算、真实灯控联调、多人实时协同编辑（首月）。

---

## 5. 范围

### 5.1 比赛版主链路（冻结）

```
预置样例 或 导入剧本
  → 离线解析（无需网络）
  → 结构校对（场次边界、人物别名、台词归属）
  → 拆解（场次、人物出场含无台词、道具、舞台说明）
  → 技术需求转译（灯光/音乐/音响/舞美）
  → 舞台画布（站位、走位、提示绑定）
  → 排练记录 → 修改确认 → 影响提示
  → 导出排演材料与部门需求单
```

**不做**：影视拍摄方案、AI 影像时间线、账号与协作、录音转写、真实灯控。

### 5.2 一个月完整产品

补齐三种制作方案与跨方案复用、版本体系与影响中心、异步协作、在线后端、AI 影像与成片导出。

## 6. 设计原则

1. 工作区负责准确，对话负责理解；AI 结果必须落回工作区成为可编辑数据。
2. 内容区分四类来源：剧本明确内容、分析解释、制作决定、执行记录。
3. 关联必须带用途，以便精确计算影响。
4. 上游变更先形成影响记录，由用户逐项决定。
5. AI 不覆盖已确认内容。
6. **主流程不依赖 AI**；AI 仅增强。
7. 不确定性显式化，不猜测填充。

## 7. 数据模型

### 7.1 ScriptData v2（向后兼容）

```
ScriptData {
  summary, scenes[], characters[], relationships[],   // 原有
  acts: Act[],
  meta: { source: 'sample'|'upload'|'generate', importedAt, parser: 'offline'|'ai' }
}
Scene { id, sceneNumber, title, location, characters[], presentCharacters[],
        props[], stageDirections[], summary, estimatedMinutes,
        rawRange: {start,end}|null, actId|null }
Character { id, name, aliases[], description }
Relationship { id, from, to, relation, needsReview, evidence: {sceneId, quote}|null }
Act { id, actNumber, title, sceneIds[] }
```

`id` 缺省规则：场次 `sc-<sceneNumber>`，人物 `ch-<name>`。

### 7.2 制作层数据（不进 ScriptData）

```
ProductionPlan {
  id, type: 'stage'|'film'|'ai', name, sourceVersion,
  segments[], cues[], briefs[], staging|null, rehearsals[], impacts[]
}
Segment { id, title, sceneIds[], rawRange, castIds[], goals[] }
Cue { id, department, sceneId,
      trigger: { type: 'line'|'action'|'entrance'|'exit'|'free', quote, offset },
      content, status, note }
Brief { id, department, sceneId, cueId|null, original, items[], uncertain[],
        priority, dueDate|null, status, owner, note }
Staging { stage: { width, depth, audienceSide, entrances[] },
          placements: { segmentId, characterId, x, y, facing }[],
          paths: { id, segmentId, characterId, points[], triggerQuote }[],
          notes[] }
Rehearsal { id, segmentId, date, location, castIds[], notes[],
            decisions[], openQuestions[], todos[] }
Impact { id, change: {kind, refId, description}, target: {kind, refId},
         reason, suggestion, status }
```

`department ∈ {lighting, music, sound, scenery}`。
`status ∈ {draft, submitted, confirmed, implemented, needsReview}`。

### 7.3 兼容

`normalizeScriptData` 补齐新字段，缺省不抛错；旧组件读旧字段继续工作。

## 8. 离线降级

```
用户操作
  ↓
本地能力层（始终可用）：解析、拆解、转译拆分、画布、导出
  ↓（可选）
远程 AI（配置可用时）：摘要、关系判断、润色
  ↓ 失败
回落本地结果，界面标注「仅本地处理」
```

- 本地解析器：识别幕/场、人物表与台词、括号提示与舞台说明；无法识别处保留原文并标记待确认。
- 拆解规则：由台词归属推导出场；由舞台说明提取道具与动作候选。
- 转译拆分：按标点与部门关键词切分，未匹配进 `uncertain`。
- 导出：浏览器内生成可打印 HTML 与 CSV。
- 两条路径产出**同一数据结构**，上层不区分来源。
- 「从想法开始」无本地等价能力：离线时按钮禁用并提示需联网；导入与样例路径完整可用。

## 10. 功能链路

**共同层**：创建/打开 → 导入或样例 → 离线解析 → 结构校对 → 拆解 → 选择方案（比赛版仅舞台）。

**舞台方案**：选场次建片段 → 配置舞台与演员（AB 角）→ 画布站位/路径/绑定 → 四部门提示 → 需求转译 → 排练记录 → 决定与影响 → 导出。

**拍摄方案（一个月）**：改编稿 → 场景与资源拆解 → 镜头与分镜 → 拍摄安排 → 场记素材 → 影响 → 导出。

**AI 影像方案（一个月）**：视觉资产 → 镜头与关键帧 → 生成任务 → 候选选用 → 连续性与时间线 → MP4 → 局部重做。

## 11. 信息架构

作品总览 ｜ 创作与剧本 ｜ 人物与剧情 ｜ 资料与资产 ｜ 舞台方案（片段/舞台与演员/调度画布/提示/转译/排练/导出）｜ 拍摄方案 ｜ AI 影像方案 ｜ 影响处理 ｜ 任务讨论 ｜ 生成任务 ｜ 交付记录。

比赛版为单页步骤流 + 结果页多标签，不引入路由库。

## 12. 技术架构

```
shared/    契约、归一化、离线解析器、规则、样例、导出
client/    React + Vite → dist（比赛版全部能力）
server/    Express（开发与完整版增强，比赛版不依赖）
```

| 模块 | 位置 |
| --- | --- |
| 离线解析器 | `shared/parser/index.js` |
| 拆解与转译规则 | `shared/rules/{breakdown,briefs,impact}.js` |
| 样例 | `shared/samples/oneAct.js` |
| 导出 | `shared/export/index.js` |
| 引擎（远程优先/本地兜底） | `client/src/engine/index.js` |
| 制作方案状态 | `client/src/store/plan.js`（纯函数 reducer） |
| 持久化 | `client/src/store/project.js`（IndexedDB，内存降级） |
| 舞台画布 | `client/src/components/StageBlocking.jsx`（SVG） |

**必须同步修改**：`shared/package.json` 的 `exports` 需加入 `./parser/index.js`、`./rules/*.js`、`./samples/oneAct.js`、`./export/index.js`。

工程规则：乐观并发、派生数据带 `rawRange`、写操作幂等、导出可追溯。

## 13. 视觉设计

**剧场文本风**：文本区浅色纸张、衬线标题、墨色正文；舞台画布/预览局部深色；朱红仅用于关键动作与状态。

- 字体使用**系统字体栈**（`Songti SC`/`SimSun`/`STSong` 与 `PingFang SC`/`Microsoft YaHei`），不打包字体文件、不引用外部 URL。
- 状态可视：原文 / AI 建议 / 用户修改 / 已确认；待复核 / 处理中 / 已完成。
- 中文排版：剧本缩进、全角标点、人物名对齐、字号行距可调。
- 用户已确认执行**全站视觉改版**，为比赛版必做项。

## 15. 验收

**比赛版**：断网下从样例走完七步并导出非空材料；删除被绑定的台词后能指出受影响提示并允许重新绑定；转译条目保留原话、条目与待确认；`dist` 静态打开无错误；原有 56 项测试继续通过。
