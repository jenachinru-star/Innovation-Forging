# 编导 AI 工作台

把零散的创作想法和口头沟通，变成各部门同步、可执行、可追溯的工作材料。

面向学生剧组与小剧团的导演、编剧、舞台监督：规模小、预算低、一人多岗、多在小剧场演出。

## 核心链路

导入 / 样例 → 离线解析 → 结构校对 → 拆解 → 技术需求转译 → 舞台画布与提示 → 排练记录与影响 → 导出

- **导入 / 样例**：上传 `.txt` / `.md` / `.docx` 剧本，或直接使用内置原创独幕话剧样例。
- **离线解析**：识别幕、场、人物台词与舞台说明；无法识别处保留原文并标记待确认。
- **结构校对**：核对场次边界、人物别名与台词归属。
- **拆解**：得到场次、人物出场（含无台词出场）、道具与舞台说明。
- **技术需求转译**：把导演原话按部门拆成可执行条目，保留原话、条目与待确认项。
- **舞台画布与提示**：可编辑的站位、走位，以及绑定到台词 / 动作的部门提示。
- **排练记录与影响**：记录排练决定，逐项确认上游改动带来的影响。
- **导出**：在浏览器内生成可打印的排演材料与部门需求单。

## 关键设计

- **四类来源区分**：内容区分剧本明确内容、分析解释、制作决定、执行记录，避免 AI 建议与已确认事实混淆。
- **关联带用途**：提示、需求、走位等关联都记录用途，以便精确计算上游改动的影响。
- **影响逐项确认**：上游变更先形成影响记录，由用户逐项决定，不自动覆盖已确认内容。
- **AI 仅增强**：主流程不依赖 AI；离线时导入与样例路径可完整运行，界面标注「仅本地处理」。

## 四部门

灯光、音乐、音响、舞美 / 服化道。「音乐」与「音响」作为两个独立部门建模。

## 本地运行

```bash
npm install
npm run dev:server   # 启动 Express 服务
npm run dev:client   # 启动 Vite 开发服务器
```

## 构建

```bash
npm run build
```

构建产物输出到**项目根目录** `dist/`（`dist/index.html` 为入口），可直接用任意静态服务器托管，无需启动 Node 服务。

## 已知边界

- 不做真实灯控对接。
- 不做多人实时协同。
- 离线下「从想法开始」不可用（无本地等价能力，按钮禁用并提示需联网）。
